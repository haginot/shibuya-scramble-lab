Local export `NOTICE` includes the original statistical, train and acquisition provenance. Statistics are factual source context and are not relicensed; the Halloween routing scenario uses 960 invented arrivals rather than a measured crowd census. The film includes the toy-model notice throughout and a brief source card in the 18-second loop. MP4 metadata repeats the main credits. No audio track is used.

Generation tools (external programs, not bundled art assets): Playwright Apache-2.0, Python PSF, Node.js MIT, FFmpeg/libx264 system GPL-enabled build. No online publication is part of recording.

The sandbox-compatible recorder exports the **actual same three.js scene** (visible drawable objects, triangle positions/normals/UVs, generated canvas textures, transforms and agent states) to a local cache, then uses the original `tools/halloween_raster.c` CPU rasterizer. It uses perspective-correct UVs, a depth buffer, procedural emissive maps, alpha sprites and fog, with Pillow composing the same bilingual graphic layout. This adds no outside art asset. The code is project MIT; NumPy BSD-3-Clause and Pillow MIT-CMU are local generation dependencies. It is explicitly recorded as CPU rendering in `recording.json`; interactive WebGL performance is not inferred from encoding speed.

Iteration 1 (2026-10-21): 18-second full-frame puzzle-ad composition, shared closed
witch orbit and camera path, self-made coupon ticket graphics, emissive bloom,
round crowd-dot mask, larger procedural windows and fictional shop kiosks.
The latte offer is fictional; changing its copy does not change any routing
coefficient. The paired replay restarts at film second 6 (sim second 300).
The final comparison uses full 900-second results, with matched images at 900s.
The 18-second endpoint restores the opening camera, unpromoted model state,
witch, trail, ghost phase and bubbles. No external art or audio was added.


Iteration 2 (2026-10-21): the main intervention is five fictional peripheral events.
`shibuya_halloween_region.json` contains **47,816** source buildings within a 3km
radius, from the same licensed PLATEAU Shibuya 2023 CityGML archive. Acquisition
script `tools/fetch_halloween_region.py` records each archive member's SHA-256.
For distant rendering, the tallest actual building per 42m tile is shown using
its source bounding box/height; no invented building infill. Some foreground
near buildings are omitted to keep the complete scramble visible. Source data
is retained unchanged, including the original crossing file.

Coverage: Shinsen, Harajuku, Yoyogi and Ebisu have source buildings near the hubs.
Omotesando's eastern area is outside this municipal extract: the fictional hub
is a schematic marker and no replacement real-world geometry is invented.
Event positions, walking corridors, station access and regional railway curves
are authored schematic interpretation; they are not a navigable map. Assumed
Yamanote / Inokashira service is illustrative, not an actual timetable.

All six costume templates (witch hats, pumpkin heads, capes and lanterns), toy
station, elevated train, generic original dog statue / meeting square, giant
fictional advertising panels and regional festival stages are self-made meshes
or Canvas textures. The dog is not a scan of a statue. Only fictional shops or
events appear in advertisements. No external decorative assets or audio.

The model uses matched seeded demand and 0.25s social-force steps. All displayed
peak densities, per-district counts, arrival ratios and best-event values come
from `out/media/shibuya-halloween-metrics.json`. Participation and capacities are
assumptions. Density colour derives from local counts, never the event flag.
Regional particles represent actual travelling/arrived agent states, and trains
follow representative boarded agents. Train meshes are enlarged in the aerial
view. The continuous ribbon is a schematic guide, not additional people.

Iteration 3 (2026-10-21): replaced generic hubs with five distinct original
procedural attractions: witch-hat costume stage, parade floats, ghost-lantern
garden, light-arch promenade and pumpkin food tents. The authored attraction
markers and aerial trains are enlarged for visibility; their dimensions are
illustrative. Distant LOD now uses one actual source building per 84m tile.
Fictional shop-only ad screens have authored facade backing and corrected
front-facing text. Station/elevated rails and original meeting-square dog remain.
No new downloaded assets, real logos, real events or audio.

Heat hue is based on the actual running peak average density in the fixed
24m-radius disk (matching the comparison statistic), with
a fixed cyan-to-cherry range of 0.26–0.33 people/m². Local counts determine
opacity; the event flag never sets heat colour. This disk includes the crossing
and its immediate edges: it is an area average, not a local crowd-density maximum.
Comparison images use identical camera, green phase and model second 1084.
The peak statistic is the maximum over both full matched 1800s trials. The
return shot replays the same green window from 1084s, retaining the crowd and
continuing their actual motion instead of showing the much emptier trial tail. Purple witch/signal replay bridges reset.
District results and both event ranking criteria accompany the video in RESULTS.txt.

Iteration 4 (2026-10-22): original procedural blueprint grid, source-footprint
strokes and scan sweep; transient flat-to-full-height city animation; daylight,
dusk and night light states; ×6→×100 indicator and sliding data panels. Blueprint
shop visits are actual model shop visits (zero: shops are scenery, not the
intervention), alongside the current central count. All source geometry files
remain unchanged. The animation scales the rendered city vertically only during
the blueprint transition, then restores the original heights.

The regional section is shorter, with persistent source-positioned district names,
gapped amber walking guides and distinct mint/lilac railway routes. Schematic
station pulses require actual model rail passengers near boarding/alighting;
enlarged train meshes still follow representative boarded people. Boarding and
completed-arrival counters are actual state totals. Regional train/attraction
sizes remain illustrative. No new map data or decorative assets were fetched.

The return has an explicit OFF→ON paired replay: a procedurally generated soft
wipe between rendered baseline/event states at the same camera and model time.
This is a comparison transition, not a claim that a peak measurement falls over
those seconds. The main result uses two large matched-green views and five
compact OFF→ON district bars; Yoyogi is highlighted by completed arrivals. Full
precision, calibration and mode totals remain in metrics.json and RESULTS.txt.
A MODEL RESET cue returns through the packed baseline into the flat blueprint;
the 20-second endpoint restores the opening scene, captions and counters.
